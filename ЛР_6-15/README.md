# Лабораторные работы № 6–15. Игра «Змейка» (вариант 10)

## Общие сведения

**Дисциплина:** Паттерны проектирования  
**Язык программирования:** C#  
**Среда разработки:** Microsoft Visual Studio 2022  
**Платформа:** .NET Framework 4.8  
**Тип приложения:** консольное приложение

В качестве предметной области выбрана игра «Змейка». В проекте последовательно рассматриваются паттерны, указанные в методических указаниях для лабораторных работ № 6–15. Для каждого задания подготовлен отдельный сценарий, который показывает назначение основных классов и взаимодействие объектов.

## Содержание лабораторных работ

| № | Паттерн | Реализация в проекте |
|---:|---|---|
| 6 | Заместитель (Proxy) | `SettingsProxy` контролирует доступ к чтению и записи настроек и проверяет допустимое значение интервала игры. |
| 7 | Команда (Command), Итератор (Iterator) | `TurnCommand` и `MoveCommand` представляют действия игрока; `CommandQueue` выполняет команды по очереди; `SnakeIterator` перебирает сегменты змейки. |
| 8 | Цепочка обязанностей (Chain of Responsibility) | `WallCollisionHandler` и `BodyCollisionHandler` последовательно проверяют столкновение головы змейки со стеной и собственным телом. |
| 9 | Посредник (Mediator), Снимок (Memento) | `GameMediator` уведомляет игровые компоненты об изменении счёта; `GameSnapshot` сохраняет и восстанавливает состояние игры. |
| 10 | Наблюдатель (Observer), Состояние (State) | `GameEventSource` рассылает события подписчикам; `GameStateContext` переключает состояния игры: выполнение, пауза и завершение. |
| 11 | Стратегия (Strategy), Шаблонный метод (Template Method) | `BoundedMovement` и `WrapMovement` задают разные алгоритмы перемещения; `GameLoopTemplate` определяет общий порядок обработки кадра. |
| 12 | MVC | `SnakeModel` содержит игровую модель, `SnakeView` выводит данные, `SnakeController` обрабатывает команды управления. |
| 13 | CQRS | `ScoreCommandHandler` обрабатывает команды изменения счёта, `ScoreQueryService` выполняет запрос текущего значения. |
| 14 | Repository | `IRecordRepository` отделяет работу с рекордами от конкретного способа хранения; `InMemoryRecordRepository` использует коллекцию `Dictionary`. |
| 15 | Producer–Consumer | `BackgroundTaskQueue` принимает фоновые задачи в потокобезопасную очередь и обрабатывает их отдельным рабочим потоком. |

## Требования для запуска

1. Windows 10 или Windows 11.
2. Microsoft Visual Studio 2022 с установленной рабочей нагрузкой **Разработка классических приложений .NET**.
3. Пакет разработчика **.NET Framework 4.8 Developer Pack**.

## Сборка и запуск

1. Распаковать архив проекта в отдельную папку.
2. Открыть файл `SnakeLabs.sln` в Visual Studio 2022.
3. В обозревателе решений выбрать проект `SnakeLabs` как запускаемый.
4. В меню **Сборка** выбрать **Собрать решение** (или нажать `Ctrl+Shift+B`).
5. Если ошибок сборки нет, запустить программу клавишей `Ctrl+F5` (без отладки) или `F5` (с отладкой).
6. В окне консоли проверить вывод демонстрационных блоков ЛР № 6–15.

При запуске программа по очереди выводит заголовок каждой лабораторной работы, выполняет небольшой сценарий и показывает результат. После завершения всех сценариев выводится сообщение о завершении демонстрации.

## Проверка отдельных заданий

Для проверки работы паттернов можно ориентироваться на следующие фрагменты вывода:

- **ЛР 6:** сообщение о проверке доступа и сохранении настроек; вывод установленного интервала.
- **ЛР 7:** сообщения о выполнении команд и координаты/сведения о сегментах змейки, полученные через итератор.
- **ЛР 8:** результат проверки предполагаемой позиции головы обработчиками столкновений.
- **ЛР 9:** уведомления компонентов о новом счёте и восстановление ранее сохранённого состояния.
- **ЛР 10:** уведомления подписчиков, выполнение хода в состоянии `PlayingState` и отсутствие хода в состоянии `PausedState`.
- **ЛР 11:** результат выбранной стратегии перемещения и последовательное выполнение шагов игрового цикла.
- **ЛР 12:** изменение модели через контроллер и вывод обновлённых данных представлением.
- **ЛР 13:** начисление очков командами и получение итогового значения отдельным запросом.
- **ЛР 14:** сохранение рекорда и получение записи из репозитория.
- **ЛР 15:** добавление задач в очередь и их выполнение рабочим потоком до завершения очереди.

## UML-диаграммы

Для каждой лабораторной работы подготовлены два файла:

- файл `.puml` — текстовое описание диаграммы;
- файл `.png` в каталоге `docs/uml/png` — изображение диаграммы, которое можно просматривать отдельно и использовать в отчёте.

Диаграммы показывают основные классы и интерфейсы, наследование, реализацию интерфейсов и связи между объектами. Изображения диаграмм также вставлены в соответствующие отчёты.

## Отчёты

В каталоге `docs/reports` находятся отдельные документы DOCX для лабораторных работ № 6–15. В каждом отчёте представлены:

1. титульный лист;
2. цель работы;
3. краткое теоретическое обоснование паттерна;
4. описание проектирования и реализации для варианта 10;
5. UML-диаграмма классов;
6. описание результата выполнения программы;
7. вывод по лабораторной работе.

## Примечание по реализации

Проект является учебной демонстрацией паттернов на примере предметной области «Игра Змейка». Он не предназначен для полноценной игры с графическим интерфейсом: основной результат работы — программная реализация паттернов и демонстрация их взаимодействия в консольном приложении.
